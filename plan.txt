ПЛАН: МОДЕРНИЗАЦИЯ ФИЛЬТРАЦИИ КАНАЛОВ В GRAPHRAG

ПРОБЛЕМА:
Сейчас кнопка «Отключить канал» в боте влияет только на загрузку новых новостей. 
Старые данные из отключенных каналов остаются в Qdrant и Neo4j и попадают в ответы модели.

РЕШЕНИЕ (БЕЗ ПЕРЕЗАПОЛНЕНИЯ БАЗЫ):

1. Изменение логики записи (Extraction Service):
   - В Neo4j при создании связей (Relationships) теперь будем сохранять поле `source` (название канала), а не только хэш det_id.
   - Это позволит фильтровать граф знаний по источникам «на лету».

2. Миграция существующих данных (Migration Script):
   - Напишем скрипт, который сопоставит новости из PostgreSQL (где есть имена каналов) со связями в Neo4j (через хэширование det_id).
   - Скрипт проставит поле `source` для всех старых данных.
   - ПЕРЕЗАГРУЗКА И ПОВТОРНЫЙ ВЫЗОВ LLM НЕ ТРЕБУЕТСЯ.

3. Обновление поиска (Query Service):
   - Перед каждым запросом сервис будет читать .env.scraper, чтобы получить актуальный список активных каналов.
   - В Qdrant будет добавлен фильтр: `must match source IN [active_channels]`.
   - В Neo4j Cypher-запрос будет дополнен условием: `WHERE r.source IN [active_channels]`.

РЕЗУЛЬТАТ:
Мгновенное управление контекстом. Отключили канал в боте — модель тут же «забыла» всё, что он писал, включая историю.
